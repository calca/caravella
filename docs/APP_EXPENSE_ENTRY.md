# App: Expense Entry

Covers `lib/manager/expense/**` — the expense form, attachments, voice input, receipt scanning, and the location subsystem.

## State/controller split

`ExpenseFormState` (`state/expense_form_state.dart`) is an **immutable** value object: `category`, `amount`, `paidBy`, `date`, `location`, `name`, `note`, `attachments`, `assignedTo`, `entryCurrency` (the group's `SecondCurrency` when `amount` is typed in it; `groupAmount` converts, `original` is the `OriginalAmount` saved with the expense), plus UI flags (`isDirty`, `isExpanded`, `isRetrievingLocation`) and per-field `*Touched` flags for validation-feedback timing. Exposes `isNameValid`/`isAmountValid`/`isPaidByValid`/`isCategoryValid(categories)`/`isFormValid(categories)`, factories `.initial(...)`/`.fromExpense(...)`, and `toExpense()`.

`ExpenseFormController` (`state/expense_form_controller.dart`, `ChangeNotifier`) owns the `TextEditingController`s, `FocusNode`s, and `GlobalKey`s (for scroll-to-field). Fields are marked "touched" only **on blur** (not on autofocus) so error styling doesn't flash immediately. All real validation is delegated to `ExpenseValidationService`.

## Component composition

`ExpenseFormComponent` (`components/expense_form_component.dart`) is the actual widget used everywhere, built from one `ExpenseFormConfig` (its constructor, or the `.create`/`.edit` factories; `isEditMode` comes from whether `initialExpense.id` is set).

Its `initState` builds an `ExpenseFormLifecycleManager` (controller construction, optional `FormScrollCoordinator`, auto-location retrieval, "newly added category" auto-select) and then an `ExpenseFormOrchestrator` (owns `saveExpense`/`deleteExpense`/`expand`, wires parent-supplied callbacks like `onSaveCallbackChanged` so an external toolbar can trigger the form's internal save).

Widget tree in `build()`: `ExpenseFormCompactHeader` ("In group: <title>", hidden by the current callers) → `ExpenseFormFields` (the amount — in a group with a second currency (`ExpenseFormConfig.secondCurrency`) a quiet grey line of fixed height under it: "in kr" (dotted underline) types it in that currency, then "= 38.69 € · in €"; a new expense starts in the currency of the group's latest one (`startInSecondCurrency`), an expense typed in kr opens in kr at its own rate; whole amounts without decimals, otherwise always two, via `ExpenseFormController.formatAmountForInput`, so an edited 54.5 reads "54.50" — then the description as a raised rounded field (`FormTheme.getCardDecoration`), then paidBy and category; touched-and-invalid fields get a subtle red-tinted `AnimatedContainer`) → `ExpenseFormExtendedFields` → `ExpenseFormActionsWidget` when `showActionsRow` (round mic and scan buttons, then a full-width stadium Add expense / Save button; delete only when editing in a sheet). In the quick-add sheet (`!fullEdit`, not editing, `onExpand` set — Home) the details are left out: `ExpenseFormExtendedFields(onMoreDetails:)` shows only a dashed **More details** pill calling `orchestrator.expand()` (Home opens `ExpenseFormPage` with what was entered so far: `AddExpenseController._expandToFullPage` closes the keyboard, pushes the page with `_SheetToPageRoute` — a slide up from the bottom with `AppMotion.sheet`, so the sheet seems to grow to full screen — and removes the sheet route underneath once the page has arrived; that page doesn't autofocus the amount, `ExpenseFormPage(autofocusAmount: false)`, so the keyboard doesn't come back up), plus the attachments strip when there are attachments (a scanned receipt / photo). There is no swipe-up gesture any more (it was a hidden action). Without `onExpand` (the notification's sheet) the details stay in the sheet. In both sheets (`!fullEdit`, not expanded) `ExpenseFormFields(compactPills: true)` keeps paid-by and category on one line each (`ChipSelectorRow.singleLine`): the pills that fit, then a dashed "+N" pill on the same line that expands the row in place (all items wrap, then a dashed add pill turning into an inline name field; no second sheet, so the keyboard stays open); the current choice always stays visible.

`ExpenseFormExtendedFields` is the "Details" section: a `FormSectionLabel` over a `Wrap` of `FormPill`s (`caravella_core_ui`) — the date (`DateSelectorWidget`, "Today" or the date, opens the date picker), the place (`LocationInputWidget`: dashed "Place" when empty → `PlaceSearchPage`, the locality once set → the details sheet with current location / search / remove, a spinner with "Getting location..." while detecting), attachments (`AttachmentInputWidget(asPill: true)`, dashed; it opens the sources in place, as pills under it: take a photo, record a video, gallery, files — no sheet) and note (dashed; tapping reveals the note field and focuses it). Once there are attachments the pill is replaced by the attachments list below; an existing note shows its field straight away, under a "Note" `FormSectionLabel` (`NoteInputWidget`: the raised card field, at least 4 lines); a note opened and left empty folds back into its pill when it loses focus. In read-only groups the empty "add" pills are hidden. Automatic location detection runs once, in `ExpenseFormLifecycleManager` (create mode, address resolved), and reports its progress through `ExpenseFormController.setLocationRetrieving`, which the place pill shows; a place the user picks meanwhile is not overwritten.

Hosts: `ExpenseFormPage` (full page, for editing an expense from the group page and for "More details" from the sheet: grey `surfaceContainer` background, edge to edge, `RoundBackButton` plus round share / delete (`RoundIconButton`) when editing, the group name over a large "New expense" / "Edit expense" title, and the actions bar pinned at the bottom above the keyboard; the amount is autofocused only when adding, and not when opened from "More details") and `ExpenseEntrySheet` (the quick sheet from Home, from the group page's add buttons (FAB, empty state, welcome card — all through `AddExpenseController.showAddExpenseSheet`, with `onExpensePersisted` letting the page highlight the new row) and from the notification: same grey, the form scrolls while the actions bar stays pinned below it, above the keyboard; the sheets open with `useSafeArea` so the taller form stays below the status bar and slide in with `AppMotion.sheet`). Work that moves the layout waits for the sheet or page to finish sliding in (`routeSettled` in `coordination/route_settled.dart`): the amount's autofocus — so the keyboard rises after the sheet, not during it — and the automatic location. Opening the sheet from Home sets the group as `currentGroup`; `GroupCard` and the group page ignore that notification when the group is unchanged, so what's underneath doesn't rebuild mid-animation.

`ParticipantSelectorWidget`/`CategorySelectorWidget` (`widgets/`) render a `FormSectionLabel` ("Paid by" / "Category") above a `ChipSelectorRow<T>` (`caravella_core_ui`) — pills that wrap onto more lines, identical in compact and extended mode; payers carry their `ParticipantAvatar` initials, and the selected pill is filled in the text color. The row shows up to 4 items in whatever order the caller passes in (`ExpenseFormPage`/`ExpenseEntrySheet` pass `ExpenseGroup.getParticipantsByLastUsed()`/`getCategoriesByLastUsed()`, so the most recently used participant/category surfaces first); a group with more than 5 values collapses the rest behind a trailing "..." pill (`showSelectionBottomSheet` for the full list), and a selection picked among the hidden ones shows as its own pill before "...", which stays so the full list is always reachable. A trailing round "+" opens the same sheet in inline-add mode (`autoStartAdd`) when an add callback is supplied.

## Validation

`validation/expense_validation_service.dart` — pure static functions: `isAmountValid` (non-null & >0), `parseAmount` (normalizes comma→dot), `isNameValid`, `isPaidByValid`, `isCategoryValid` (an **empty categories list is valid** — lets a brand-new group with zero categories still save an expense), `isAttachmentCountValid`, `isLocationValid`, aggregate `isFormValid`. `errors/expense_error_handler.dart` centralizes all toast messaging via `AppToast.show` — note most of its strings are hardcoded English rather than localized (a known inconsistency to watch for when touching this file).

## Attachments

`widgets/attachments/attachment_state_manager.dart` (`ChangeNotifier`) is the business logic: picks via `FilePickerService` (camera/gallery/files), copies into `AttachmentsStorageService.getAttachmentPath(...)` (from `caravella_core`), compresses images through `ImageCompressionService` only when file size is between 200KB–50MB (skips very small/large files, falls back to a plain copy on compression failure). Tracks an `AttachmentProcessingState` (`idle/picking/compressing/saving`).

`AttachmentInputWidget` renders an "Attachments" `FormSectionLabel` with the count (up to 5), the files as `AttachmentRow`s (`widgets/attachments/attachment_row.dart`) in a raised card — a round preview (the photo itself, decoded as a thumbnail, or a monochrome icon on a grey circle for PDF / video / other files), the file name, extension and size, and a 48 dp remove button labelled "Remove <name>" — then a dashed "Add attachment" pill while there's room (a spinner in it while a file is being added). Tapping a row opens `AttachmentViewerPage` (`pages/attachment_viewer_page.dart`, driven by `AttachmentViewerController`), which dispatches per-file to `image_viewer_page.dart`, `pdf_viewer_page.dart`, or `video_player_page.dart` by extension.

## Voice input

`VoiceInputButton`/`VoiceCaptureBottomSheet` (`widgets/`; in the expense form it opens in place above the buttons, `onClose`, not as a sheet on top of the expense sheet) and the home-card `GroupCardVoiceButton` (`lib/home/cards/widgets/group_card_voice_button.dart`) all wrap `lib/services/voice_input_service.dart`'s `VoiceInputService`, which wraps the `speech_to_text` plugin across the app's 5 supported locales. It initializes with `SpeechToText.androidNoBluetooth`: otherwise the plugin asks for `BLUETOOTH_CONNECT` ("Nearby devices") together with the microphone whenever the merged manifest declares it, which happens in the Play build because of the Bluetooth sync.

- `startListening({localeId, onResult, onError, onDone})` drives the mic; errors are normalized into `VoiceInputError` (`notAvailable`/`permissionDenied`/`noSpeech`/`recognitionFailed`). When the recognizer can't start, `Permission.microphone.status` tells a refused microphone (`permissionDenied`) from a device without speech recognition (`notAvailable`); a refused microphone opens `showPermissionDeniedDialog(DeniedPermission.microphone)` ("Allow the microphone?" → Open settings) on Home's Voice, the form's mic and the voice sheet.
- `parseExpenseFromText(text, {participantNames})` is a keyword-based NL parser returning `{amount, name, category, paidBy, date}` — regex-extracts amount (multi-currency tokens), relative dates (yesterday, last week/month, weekday names — per-locale), a "paid by" participant name (matched case-insensitively against the group's participants), and an expense category (locale-specific keyword lists → `food/transport/accommodation/entertainment/shopping/health`).
- `GroupCardVoiceButton` saves the parsed expense without opening the form only when `voiceExpenseIsComplete`: an amount, a name (the description the parser keeps, e.g. "Cena" from "20 euro cena"), who paid and a category (falling back to the group's first). Otherwise it opens the form pre-filled with "Some details are missing". "20 euro" alone has no name, so it opens the form: saved directly, SQLite refused it (`expenses.name` is `NOT NULL`) while the app said "saved".
- From a group card, if amount+payer+category were all parsed the expense is saved directly (`ExpenseGroupStorageV2.addExpenseToGroup`); otherwise `ExpenseFormPage` opens pre-filled. Either path then calls `NotificationManager().updateNotificationForGroupById` and `RatingService.checkAndPromptForRating()`.

## Scroll coordination

`coordination/form_scroll_coordinator.dart` (`FormScrollCoordinator`) computes whether a field's rect is obscured by the keyboard or too near the top, and `animateTo` an adjusted scroll offset. `coordination/keyboard_aware_scroll_mixin.dart` (`KeyboardAwareScrollMixin`) is a `WidgetsBindingObserver` mixin watching `didChangeMetrics()` for keyboard height changes, invoking an overridable `scrollToFocusedField()` hook.
